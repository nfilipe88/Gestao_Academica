A carregar mapa de permissões…

Onde está o acesso parcial

  • Diário / Trabalhos: o Professor só lança notas e frequência nas turmas+disciplinas onde tem alocação registada.
  • Comunicações: o Professor não tem a opção "Toda a escola" — só turma ou aluno individual.
  • Documentos: a Secretaria gere pedidos mas não os Preços (só Gestor); o Professor só vê os pedidos endereçados a si.
  • Transferências: Gestor/Secretaria só pedem a transferência — decidir (aprovar/rejeitar) é exclusivo do Super Admin, por ser entre escolas diferentes.
  • Professores: a Secretaria aloca turma/disciplina, mas só o Gestor cria a conta de acesso.

Como isto é garantido

  • Cada pedido ao back-end passa por uma verificação de perfil antes de tocar em qualquer dado — este mapa é a documentação dessa regra, não quem a aplica; editar uma célula aqui não muda o que a API aceita.
  • Dados de escrita ficam ainda mais restritos: mesmo com "Total", uma ação só é aceite se o registo pertencer à mesma instituição de quem pede.
  • O isolamento entre escolas (multi-tenant) é reforçado a dois níveis — no código da aplicação e diretamente na base de dados.

A caminho

  • Estes seis perfis são atualmente fixos e partilhados por todas as escolas da plataforma — este mapa é, por isso, único para a plataforma toda, não por escola.
  • Perfis personalizados por escola — por exemplo, uma "Tesouraria" com acesso só ao Financeiro — estão planeados para uma fase futura.
  • Quando existirem, este mapa passará a refletir também os perfis que cada escola criar, não só os seis fixos.
